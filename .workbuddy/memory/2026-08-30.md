## 修复：重复打开网址报错（僵尸浏览器实例）
- 问题：单步执行「打开网址」后浏览器一直开着，用户手动关掉浏览器窗口（或浏览器崩溃）后，再次执行「打开网址」报错。根因是 `_browser` 单例还指向已断连的僵尸实例，`latest_tab.get()` 抛 `PageDisconnectedError`，且无检测/重试。
- 实现（`app/web_actors.py`）：

  - 新增 `_browser_alive()`（访问 tabs_count 探活，断连抛异常即判死）、`_reset_browser()`（只清单例不 quit）。
  - `get_browser()` 发现僵尸实例先清掉再按 mode 重建。
  - `open_url()` 遇连接类异常自动 `_reset_browser` 后重建浏览器重试一次。
  - `close_tab()` 对僵尸实例幂等返回"浏览器未启动"并清单例；`close_browser()` 对僵尸实例返回 False（显示"未启动"而非"已关闭"）。
- 测试：`tests/test_web.py` 新增 `TestZombieBrowser`（8 个用例：alive 检测、get_browser 重建、close_tab/close_browser 幂等、open_url 断连重试）；真实浏览器冒烟测试验证「手动关闭后再次打开不再报错」。137 个测试中仅 test_instance_lock 7 个既有失败。

## restart.bat：Ctrl+R 热键重启脚本
- 需求：写 bat 脚本运行 python main.py，控制台按 Ctrl+R 时重新运行。
- 实现：
  - `restart.bat`：`cd /d %~dp0` → `:restart` 循环 → `python restart_watchdog.py`；watchdog 退出码 0（Ctrl+R 触发）→ goto restart 重启；退出码 1（main 自行退出）→ goto :eof 结束。
  - `restart_watchdog.py`：`subprocess.Popen([sys.executable, 'main.py'])` 启动子进程，用 keyboard 库 `add_hotkey('ctrl+r')` 监听，按下则 `p.terminate()` 并返回 0；main 自行退出返回 1。热键注册失败时静默降级（不阻塞正常启动）。
- 验证：场景 A（模拟 Ctrl+R → 返回 0 重启）与场景 B（main 自行退出 → 返回 1 结束）均通过；沙箱无法注入真实键盘事件，热键依赖真实桌面环境（项目 hotkey_manager 同库已在用）。
- 修复：restart.bat 报错「'行执行' is not recognized」「'atchdog.py' is not recognized」——根因是 bat 用了 UTF-8 编码，中文 Windows 的 cmd 默认按 GBK(936) 解析 bat 文件，中文字节被误读导致命令错位。已用 Python 重写为纯 GBK 编码 + CRLF 行尾，去掉 chcp 65001；字节级验证通过（无 BOM、无 chcp、控制流完整、GBK 往返一致）。教训：**写 .bat 文件一律用 GBK 编码**（中文 Windows），不要用 UTF-8。
- 再修复：GBK 版乱码（`������`）——用户控制台当前代码页是 65001（UTF-8，可能是 Windows Terminal/PowerShell），GBK 字节被按 UTF-8 渲染。编码矛盾根源：bat 的编码必须与控制台代码页匹配，而 cmd 预扫描标签用的是启动时代码页（936/65001 不稳定）。**最终方案：restart.bat 改为纯 ASCII（全英文提示），彻底与代码页解耦**，任何终端（cmd/PowerShell/Windows Terminal）都不会乱码；中文提示去掉，功能不变。watchdog.py 是 Python 文件无此问题。教训升级：**bat 脚本若需跨终端稳定，中文注释/提示一律不用，或用 GBK+chcp 936 并确保控制台一致**。
