## 解决发布体积限制：Gitee → GitHub Releases
- 背景：Gitee 发布版本单文件上限 100MB，当前 Nuitka onefile 产物 100.7MB 传不上去。
- 用户选定方案：换 GitHub Releases（单文件上限 2GB，无需改构建）。
- gh CLI 已登录账号 xuejia92（token scopes: gist/read:org/repo）。直连 GitHub 超时，须走本地代理 127.0.0.1:7897（环境变量里的 14755 已失效）。
- 仓库 github.com/xuejia92/-（仓库名是单连字符，PUBLIC，无描述；可考虑改名）。
- 已存在 release：tag=键鼠自动化（中文 tag）、显示名 v3.0.5，曾含历史资产 default.exe。
- **关键坑**：`gh release upload` 在 Windows 下把中文文件名「清风自动化键鼠工具.exe」上传成 default.exe（gh CLI bug）；curl 上传中文名报 422 already_exists。最终用 curl 直传 ASCII 资产名成功（HTTP 201）。
- 结果：release v3.0.5（tag 键鼠自动化）现资产 QingFeng_KeyMouse_Tool.exe（100.7MB），下载链接 https://github.com/xuejia92/-/releases/download/键鼠自动化/QingFeng_KeyMouse_Tool.exe
- 上传命令（下次复用）：
  TOKEN=$(HTTPS_PROXY=http://127.0.0.1:7897 gh auth token)
  curl -x http://127.0.0.1:7897 -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/octet-stream" -X POST --data-binary "@dist/清风自动化键鼠工具.exe" "https://uploads.github.com/repos/xuejia92/-/releases/<release_id>/assets?name=<ASCII名>.exe"
  release_id 用 `gh api repos/xuejia92/-/releases -q '.[0].id'` 获取；删除资产用 DELETE /releases/assets/<asset_id>。

## 端到端发布验证（v3.1.0）+ 发布工具两个真实 bug 修复
- 用 publish_flow('3.1.0') 完整跑通：打包 1 分钟 → 创建 Release → 上传 145MB → 完成。Release：https://github.com/xuejia92/qingfeng-keymouse-tool/releases/tag/v3.1.0（资产 QingFeng_KeyMouse_Tool.exe 145.3MB）。
- **Bug 1（Bad Content-Length）**：上传用 file-like body（ProgressReader 无 fileno）时 urllib/http.client 走 chunked 编码，GitHub 资产 API 拒绝。修复：一次性 read() 字节上传。
- **Bug 2（content_type can't be application/x-www-form-urlencoded）**：_api_request 用 data 参数时未设 Content-Type，urllib 默认加 urlencoded 被拒。修复：data 非 None 时显式 application/octet-stream。
- .gitignore 补 /dist_tools、/build_tools、/nuitka-crash-report.xml。
