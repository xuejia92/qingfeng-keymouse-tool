## 打包速度优化（Nuitka）

- 重写 `build.py`：改 argparse CLI（`--clean` / `--dir` / `--jobs` / `--ccache` / `-v`），`build.bat` 加 `%*` 透传。
- **最大提速点：删除 `--remove-output`**。旧配置每次都删掉 `build_nuitka\main.build`，等于每次全量重编。
- 默认关闭 ccache（`--disable-cache=ccache`）：Nuitka 2.7 自带 ccache 会往 `main.build` 写 `ccache-*.txt` 探测文件，并行 worker 争抢报 `Permission denied` 并使构建 FATAL 失败（jobs 20 与 jobs 8 各复现一次）。加 `--ccache` 可自行尝试。

### 重要更正：#13 的前提是错的，但修复仍然成立

**实验结论（Windows / PySide6 6.x 实测）**：`QLockFile` 在 Windows 上靠**文件独占句柄**判断，不是读文件里的 PID。对照组：手工写锁文件，PID 分别填 自己(活) / 别的活进程 / 不存在的 PID / 超大 PID —— 裸 `tryLock(0)` **四种情况全部返回 True**。也就是说「进程被强杀 → 锁永久残留」在 Windows 上不成立：`TerminateProcess` 后锁文件虽残留，但句柄已被内核回收，重启照样拿到锁。实测硬杀后**锁文件只有 4.4 秒新**、持有者 PID 4860 已死，程序仍正常启动并注册 7 个热键。

所以上一轮记录的「陈旧锁导致静默退出」是**误判**：那两个残留进程（PID 30404/30792）当时是**活着的**，`tryLock` 失败是正确行为。

**#13 真正的价值在另一半**：原代码是
```python
if not lock.tryLock(0):
    QMessageBox.information(... "程序已在运行中...")
    return 0
```
——只要失败就是死路一条，没有任何继续入口。新代码改成三分支：真有实例在跑 → 报出对方 PID 并给「强制启动」按钮 + 风险说明；锁文件建不了 → 报权限错误并给出路径。pid 存活探测 + PID 复用校验（`_pid_exe_name`）作为**兜底**保留，已在 `instance_lock.py` docstring 里写清「不要把 Qt 实现细节当保证」。

### 排查工具经验（本机）

- `tasklist` 在 Git Bash / Python 下**匹配不到中文进程名**（gbk 解码后搜「清」为空）。可靠替代：ctypes `EnumProcesses` + `OpenProcess(0x1000)` + `QueryFullProcessImageNameW` 逐个比对 basename。
- PyInstaller onefile 会有**两个**同名进程（bootloader 父 + 子进程），清理时要都杀。
- `subprocess.Popen` 的父进程对象持有子进程句柄，即使 `wait()` 返回后 `OpenProcess` 仍能成功——造「已死 PID」不能这么造，要挑一个当前不存在的 PID。
- PowerShell 工具本轮 stdout 无回显，改用 Python 做进程检查。
